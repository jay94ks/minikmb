# 타깃 CDC 시리얼 중계

`tty.rs`의 단일 서비스를 egui 터미널·REST·MCP가 함께 사용합니다. 이 기능은
관리 USB 명령으로 **활성 MCU의 타깃 CDC**를 중계합니다. PC의 임의 COM 포트를
열거나 관리 포트의 baud를 변경하지 않습니다. 기능 bit1이 필요합니다.

## 명령

일반 명령에는 UID·세대를 전달하지 않습니다. 서비스가 수락 시 현재 활성 채널을
고정하고 각 USB 명령 실행 전에 재검사합니다. GUI도 표시한 채널을 고정합니다.

| MCP 도구 | REST | 본문 / 결과 |
|---|---|---|
| `tty_open` | POST `/api/v1/active/tty/open` | `{}`; 수신 시작, `stream_id` 반환 |
| `tty_close` | POST `/api/v1/active/tty/close` | `{}`; 추가 credit 중지 |
| `tty_get_status` | GET `/api/v1/active/tty` | 수신 여부, line coding, 큐·폐기·수락 카운터 |
| `tty_read` | POST `/api/v1/active/tty/read` | `max_bytes` 1~4096, 선택 `stream_id`·`cursor` |
| `tty_write` | POST `/api/v1/active/tty/write` | `bytes` 1~65536개; `complete`, `accepted`, `total`, `error` |

첫 읽기는 `{ "max_bytes": 4096 }`으로 현재 보존된 가장 오래된 바이트부터
시작합니다. 다음 읽기는 반환한 `stream_id`·`cursor`를 전달합니다. 각 클라이언트는
독립 cursor를 사용하며 다른 클라이언트가 읽었다고 데이터가 소모되지 않습니다.
`cursor == end_cursor`이면 현재 보존된 데이터의 끝입니다. 느린 독자는
`skipped`로 누락량을 확인합니다. 수신을 다시 시작하면 새 `stream_id`를 발급해
이전 cursor를 거부합니다. 채널 전환 전의 버퍼는 새 세대에서 읽지 못합니다.

## 전송과 한도

- 원문 수신 ring은 MCU당64KiB, 보존 컨텍스트는 최대64개입니다. 덮어쓰기를
  숨기지 않고 카운터로 제공합니다. UI 표시 버퍼도64KiB이며 UI 스레드는 I/O를 기다리지 않습니다.
- SYSTEM `RX_LIMIT(0x0006)`은 12바이트 `[2,0,0,0,limit:u64le]`이며 응답16바이트의
  `sent/credit`을 검사합니다. 최대32KiB 선행 credit, 잔량16KiB 이하에서 갱신합니다.
  수신 ring에 바이트를 수락한 양만 누적 허용량에 반영하며 포인터를 무한히 보관하지 않습니다.
- 수신은 자동 시작하지 않습니다. 열기 요청을 한 인증 키/클라이언트 수명이 끝나거나
  채널 전환·종료 시 추가 credit을 중지합니다. 여러 클라이언트의 같은 활성 수신 열기는
  기존 수신을 공유하며 소유자를 바꾸지 않습니다. 모든 유효 클라이언트는 수신을 중지할 수 있습니다.
- 이미 발급한 credit은 펌웨어에서 철회할 수 없습니다. 중지 뒤 남은 최대32KiB는
  앱에서 폐기하면서 절대 카운터를 추적합니다. 다시 열 때 credit을0으로 초기화하지 않습니다.
  기존 보존 데이터는 중지 직후에도 조회할 수 있습니다. 타깃 CDC 자체의 DTR을 조작하지 않습니다.
- MCU 세션별 채널2 전용 이벤트 큐를 사용합니다. 다른 채널의 이벤트 폭주는
  시리얼 큐를 덮지 않습니다. 수신 순서 유실/잘못된 길이/credit 불일치는 오류로
  표시하고 자동 수신 재개를 막습니다. 이 경우 관리 USB 세션 재연결이 필요합니다.
- SERIAL `WRITE(0x0201)`은 최대256바이트씩 순서대로 전송하고2바이트 수락 길이를
  대조합니다. 전체 메시지 송신은4개까지만 수락하며 메시지 간 바이트가 섞이지 않습니다.
  시간 초과/부분 송신을 자동 재시도하지 않습니다. `accepted`는 ACK가 확인된 prefix이며
  `uncertain:true`인 다음 조각은 실제 수신됐을 수도 있습니다. `complete:false`에서
  전체 메시지를 그대로 재전송하면 중복될 수 있습니다. USB 수락은 타깃 프로그램 처리 완료가 아닙니다.
- `STATUS(0x0202)`16바이트와 `STATS(0x0203)`8바이트는 기존 v1.0 ABI 그대로입니다.
  UI는 UTF-8/HEX, 텍스트 CRLF, 수신 표시 지우기, 전송 결과와 line coding/폐기 카운터를 표시합니다.
  부분 송신/오류에서는 입력 내용을 보존하며 전송 내용은 운영 로그에 기록하지 않습니다.

## 검증 근거와 남은 확인

모의 시험에서 96KiB 수신/64KiB 유지·32KiB 덮어쓰기, 독립 cursor, 중지 뒤 추가
credit 없음, 같은 세션 재개, 순서 유실 차단, 인증 폐기, 채널 전환 거부,
64KiB 송신의256바이트 분할, 부분 ACK 시간 초과와 자동 재시도 없음, line coding을
확인했습니다. 인증된 실제 axum/rmcp 경로도 모의 MCU로 시험했습니다.

이 시험은 **실제 타깃 CDC 송수신 실기 통과를 의미하지 않습니다.**
아직 실기 전송은 실행하지 않았습니다. Windows DPI별 터미널 배치·포커스와
실제 타깃 프로그램과의 장시간 송수신 검증도 남아 있습니다.
