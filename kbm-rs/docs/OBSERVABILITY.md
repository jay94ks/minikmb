# 동작 로그·채널 진단

2026-11-21. Electron `operation-log.ts`·`OperationLogs.vue`의 기록 정책과
MiniKMB 진단 상태를 Rust 공통 서비스로 이관했습니다. GUI·REST·MCP가 같은 상태를
사용하며 진단 조회가 HID/TTY·NCM·MSC를 켜거나 카드에 쓰지 않습니다.

## 로그 기록과 보관

- 기본 기록ON/상세OFF, 설정은 이번 실행에만 적용합니다. 일반 입력/TTY·상태 조회와
  반복 job 조회의 성공 메타데이터는 debug이며 상세를 켜야 기록합니다. 실패는 warn,
  채널/장치·서버·영상·저장소 작업 완료와 일반 제어 결과는 info/warn입니다.
- 앱 로컬 데이터의 `logs/operations.jsonl`과 `.1`..`.4`, **최대5개·각4MiB**를
  사용합니다. JSONL 행은 최대2KiB, 최근300건과 대기1,024건을 메모리에 보관합니다.
- 생산자는 유한 메모리 큐에만 추가하고 파일 I/O를 기다리지 않습니다. 전용 워커가
  약250ms마다 기록하며 명시적 flush/설정 작업도 별도 워커에서 수행합니다.
- 큐가 가득 차면 최근 표시를 유지하고 파일 기록 누락 카운터를 올립니다. 파일 쓰기
  실패·잠금 경합도 제어를 중단시키지 않고 경로를 가린 오류/누락으로 알립니다.
  부분 기록됐을 수 있는 실패 배치는 전체를 보수적으로 누락 집계하며 재전송하지 않습니다.
- 별도 OS 잠금으로 여러 Native 프로세스의 파일 회전/append 경합을 막습니다.
  회전은 정해진 로그 파일만 대상으로 하며 다른 파일을 삭제하지 않습니다. 종료 시
  대기 기록을 처리하고 워커를 join합니다.

로그 API는 임의 문자열/필드 맵을 받지 않습니다. 이벤트 enum과 고정 메타데이터 필드만
받으며 UID, 소스 상수인 명령/오류 코드, 세대/세션, 성공/불확실 여부, 바이트/개수·
설정 불리언으로 제한합니다. **키 usage/버튼·좌표·이름·MAC·API 키·ticket·TTY/파일/패킷
본문·호스트 경로·원시 오류 메시지를 기록하지 않습니다.** 사용자 입력을 JSON으로
변환해 로그에 넣는 경로도 없습니다. 상세를 켜도 이 제한은 유지합니다.

입력의 DOWN/UP·클릭·키 조합은 결과 메타데이터만, SD job은 실제 완료/실패·정리 상태만
기록합니다. 영상은 첫 프레임 대기/수신·중단·실패·이전 모드 복원·오래된 프레임으로
상태가 바뀔 때 기록하며 프레임마다 로그를 추가하지 않습니다. 실제 OS의 키 동작이나
화면 내용, WOL 기상 여부를 로그 성공으로 추정하지 않습니다.

GUI의 동작 로그에서 파일 기록/상세, 경고·오류만/활성 UID만, 이벤트·UID 검색,
최근 로그 복사, 대기 기록 저장과 **로그 폴더 열기**를 제공합니다. 폴더 열기는 GUI·API
모두 정해진 앱 로그 디렉터리만 대상으로 하며 호스트 경로나 URL을 인자로 받거나
응답하지 않습니다. Windows의 [ShellExecuteW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew)에
명시적으로 요청하며 STA COM을 초기화/정리합니다. OS 요청 수락과 실제 창 표시를
구분해 `requested:true,confirmed:false`를 반환합니다. 발신 직전에 키/클라이언트·앱
종료 상태를 다시 검사합니다. 목록의 시각은 UTC이며 JSONL의 `time_ms`는 Unix milliseconds입니다.
최근 목록은 이번 실행의 기록이며 기존 파일을 자동 파싱하거나 가져오지 않습니다.

## 캐시된 채널 진단

활성 UID/세대를 고정하고 기존 관리 워커가500ms마다 받는 protocol v1 STATUS64를
보관합니다. 펌웨어 `management_protocol.c::Status()`와 대조한 필드는 다음과 같습니다.

| 바이트 | 형식 | 내용 |
|---|---|---|
| 0,8 | u64le,u32le | MCU 가동 ms, feature bits |
| 12..15 | u8 각1개 | 타깃·저장소 상태, 관리 CDC 열림, 네트워크 연결 |
| 16,20,24 | u32le | 저장소 job/image/upload ID |
| 28,32,36 | u32le | MCU 로그 누락, CRC 오류, 프레이밍 오류 |
| 40,48 | u64le | 저장소 수신/전체 바이트 |
| 56 | u16le | 저장소 마지막 오류 |
| 60 | u32le | HID/저장소 이벤트 누락 합 |

응답은 정확히64B여야 하며 MCU 상태를 수신하지 않았으면 `transport.mcu`/transport는
null입니다. 최근1.5초를 벗어나거나 시계가 뒤로 이동했으면 `mcu_fresh:false`로
표시합니다. MCU 가동 시간과 호스트의 수신 시각을 혼동하지 않습니다.

호스트 관리 세션·event gap/CRC 거부, 입력 준비/누른 개수/해제 미확인, 영상 모드·
프레임 수신 시각, 조회된 TTY 수신/누락·송신 카운터, NCM 상태/카운터와 저장소 job
종류·진행·오류 코드도 제공합니다. 조회가 TTY 수신을 시작하거나 매체/네트워크를
연결하지 않으며 수신 데이터·이미지/채널 이름·파일 본문을 읽지 않습니다. 실제 캡처
프레임과 MCU 완료·실제 타깃 OS 동작은 별개입니다. 미수신 값을0/정상으로 꾸미지 않습니다.

## REST·MCP

아래5개를 더해 현재 공통 명령은50개입니다. 모든 도구는 기존 Bearer 키 인증·키별
세션 폐기 정책을 사용합니다. 일반 요청에 UID/UID 배열·query·경로를 추가할 수 없습니다.

| MCP 도구 | REST | 입력 |
|---|---|---|
| `logs_get_state` | GET `/api/v1/logs` | 없음 |
| `logs_configure` | POST `/api/v1/logs/configure` | `{"enabled":true,"verbose":false}` |
| `logs_flush` | POST `/api/v1/logs/flush` | `{}` |
| `logs_open_folder` | POST `/api/v1/logs/open-folder` | `{}`; 고정 앱 폴더 열기 요청 |
| `diagnostics_get` | GET `/api/v1/active/diagnostics` | 없음 |

로그는 앱 전역 정보/설정이므로 active가 없어도 사용할 수 있습니다. 진단은 현재
active 하나만 사용하며 없으면 `NO_ACTIVE_CHANNEL`, 조회 중 바뀌면 `STALE_OPERATION`을
반환합니다. 로그 제어는 최대2개로 제한하고 실행 전 키/클라이언트와 앱 종료 상태를
검사합니다. 파일 쓰기 오류는 `LOG_IO`로 알리며 상태의 `write_error`에도 남깁니다.
원격 상태에는 로그 디렉터리·원시 OS 오류·키 원문을 포함하지 않습니다.

## 검증 범위

자동 시험은 임시 디렉터리·모의 MCU/입력과 앱 소유 loopback만 사용합니다.
최근/대기 한도·debug/OFF, JSONL 회전/정렬·다른 파일 보존, OS 잠금/실패 시 원본 보존,
누락/오류 경로 가림, 종료 flush/join과 이후 추가 거부를 확인합니다. 영상은 같은
스트림 중복 억제·첫 프레임/오래됨/실패/복원을 검사합니다. STATUS64의 실제 offset·
64B 길이·신선도, 캐시 조회의 무장치 명령, 원래 UID/세대와 키 폐기·알 수 없는 인자,
이름/입력값 비기록과 실제 job 완료 로그도 모의로 검증합니다. 기존 인증 REST/MCP
통합 시험에도 로그·진단 조회를 연결했습니다.

실제 장치 진단·장시간 로그/강제 종료·느린/가득 찬 파일 시스템·Windows 폴더 열기와
DPI/키보드 조작 수용 시험은 별도로 남아 있습니다. 장치 없는 자체 UI 렌더는 배치
검증 근거이며 실제 장치 기능/OS 동작 완료의 근거로 삼지 않습니다.
