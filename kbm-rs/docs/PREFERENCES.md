# 채널 설정 저장·Electron 이관

2026-11-21. `preferences.rs`와 설정 화면은 영상 모드·NCM DHCP 설정·포워딩 규칙·
WOL 설정을 실리콘 UID별로 저장합니다. 채널 이름과 별도4KiB 값은 기존처럼 SD의
펌웨어 프로토콜을 사용합니다. 호스트 설정으로 BOARD.ID를 대체하지 않습니다.

## 저장과 적용

- Windows `ProjectDirs`의 MiniKMB Native 로컬 데이터 디렉터리에 `preferences.json`을
  보관합니다. version1·revision·채널 목록이며 최대64개 채널/1MiB입니다.
- 영상은 실제 첫 프레임을 받은 스트림만 저장합니다. 실패한 요청·이전 모드로
  복원된 요청은 저장하지 않습니다. 다음 명시적 채널 제어에서 UID의 모드를 사용합니다.
- NCM 설정은 OFF에서 저장합니다. 포워딩 규칙 적용과 성공한 시작도 저장합니다.
  저장 실패 뒤 새 포워딩은 중지하고 오류를 반환합니다. 규칙 변경이 실행 중 서비스를
  몰래 바꾸지 않으며 시작 시 현재 NCM 서브넷과 다시 대조합니다.
- 앱 시작 시 active 없음·영상 닫힘·네트워크/포워딩/REST/MCP/특수 키 OFF입니다.
  WOL 설정의 enabled 값도 패킷 전송 명령이 아닙니다. 별도의
  [WOL 보내기](WAKE.md) UI/API로 명시적으로 발신합니다.
- API 키는 별도 다이제스트 저장소를 사용합니다. 이 파일에 원문 키·입력 내용·
  파일 본문·업로드 ticket·호스트 경로를 넣지 않습니다.

저장은 별도 워커에서 수행합니다. UI/네트워크 상태 잠금을 보유한 채 파일을 쓰지
않습니다. 같은 디렉터리 임시 파일을 flush·sync한 뒤 원자적으로 교체합니다.
별도 잠금 파일의 OS 잠금과 이전 원문 바이트 대조로 다른 프로세스의 저장을 감지합니다.
충돌 시 기존 파일을 덮어쓰지 않고 다시 불러오기를 요청합니다. 잠금은 Rust 표준
[`File::try_lock`](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)을 사용합니다.

손상·미지원 버전·중복 UID·초과 크기는 자동 초기화하지 않습니다. 마지막 정상
메모리 값과 원본 파일을 보존하며 저장을 차단합니다. 설정 화면에서 다시 불러오거나
확인 후 원본을 `preferences.invalid-<난수>.json`으로 보관하고 초기화할 수 있습니다.
복구 전에 외부에서 정상 파일로 고쳐졌으면 초기화를 거부합니다. 저장/읽기 오류는
설정 화면과 원격 제어를 포함한 공통 화면에 표시합니다.

## Electron v1.0에서 가져오기

원래 Electron 프로필/LevelDB를 직접 수정하거나 해석하지 않습니다. 기존 앱의
localStorage 값을 읽어 JSON으로 내보낸 다음 Rust 앱에서 검토하여 적용합니다.
Node는 개발용 내보내기 도우미일 뿐 Rust 앱의 실행 의존성이 아닙니다.

1. 기존 MiniKMB 앱의 개발자 도구 콘솔을 엽니다.
2. 저장소의 [내보내기 도우미](../../work/export-minikmb-preferences.cjs) 내용을
   콘솔에서 실행해 `minikmb-electron-settings.json`을 내려받습니다. 도우미는 원래
   localStorage를 변경하지 않고 `minikmb.settings.<UID>`·`minikmb.video.<UID>`만 읽습니다.
3. Rust 앱의 **설정 → Electron 설정 JSON 가져오기**에서 파일을 고릅니다.
4. 채널/새 항목/기존 값 유지/제외·오류 항목 수를 검토한 뒤 **가져오기 적용**을 누릅니다.

파일 선택·읽기는 백그라운드 작업입니다. 원본 파일은 읽기 전용으로 열고 저장하지
않습니다. 이미 Rust에서 저장한 각 필드를 우선하며 없는 필드만 채웁니다. 빈 규칙
목록이나 기본 모드도 명시적으로 저장된 값이면 유지합니다. 미리보기 이후 설정이
바뀌면 적용을 거부해 새 변경을 잃지 않게 합니다.

영상 auto/1080/720/480 및 width/height/frameRate, DHCP의 camelCase 필드,
포워딩 port0, WOL MAC/localAddress를 변환합니다. MiniKMB는 UID별 채널이므로
port1 규칙은 다른 채널로 추측하지 않고 별도 오류로 알립니다. MAC은 검증 후 정규화합니다.
중복 키·정규화 후 같은 UID/종류의 별칭·모호한 파일은 거부합니다. 관련 없는 키는
보관하지 않습니다. 채널 이름·RP2040 화면 매핑·활성 UID·서버/입력 활성 상태는 이관하지
않으며 회로도 기준 자동 묶음을 유지합니다.

## 채널 카드 정렬

채널 목록에서 카드 왼쪽의6점 핸들을 드래그합니다. 대상 카드 위쪽 절반에
놓으면 앞, 아래쪽 절반에 놓으면 뒤로 이동하며 삽입 위치를 선으로 표시합니다.
목록 가장자리에서 드래그를 유지하면 자동 스크롤합니다. 이름 변경·제어 버튼은
기존 클릭 동작을 유지합니다.

순서는 로컬 `preferences.json`의 `channel_order`에 UID로 자동 저장합니다.
기존 파일에 해당 필드가 없어도 읽을 수 있습니다. 검색으로 가린 카드와
연결이 끊긴 채널의 순서도 보존하며 새 채널은 저장된 채널 다음에 표시합니다.
재연결·앱 재실행·이름 변경 뒤에도 순서를 유지합니다. 최대64개 UID를 보관합니다.
UI와 REST/MCP 채널 목록이 같은 순서를 사용하며 채널 번호·장치 매핑·활성 선택은
정렬의 영향을 받지 않습니다. 파일 외부 변경/저장 실패 시 원본을 덮어쓰지 않고
기존 toast로 오류를 알립니다.

## 검증 범위

자동 시험은 임시 파일/모의 MCU/장치 없는 영상 프레임으로 다음을 확인합니다.

- 재실행 왕복·채널 격리·64개/1MiB·중복 UID·unknown 필드·실패 시 원본 보존.
- OS 잠금·오래된 인스턴스·외부 변경·손상 후 재불러오기/명시적 보관·외부 복구 우선.
- 기존 Rust 값 우선·입력 정규화·예외 port1·중복 키/별칭·미리보기 revision 경합.
- 첫 프레임 후 한 번 저장·설정 재실행 시 영상/서비스 무자동 시작.
- 관리자의 저장/재로딩에서 모의 장치 명령·listener가 열리지 않음.
- 내보내기 도우미의 허용 키만 읽기·원본 불변·비밀 값 제외·크기 제한.

실제 Electron 콘솔→파일 선택기 조작과 Windows 강제 종료/잠금/DPI 회귀는 아직
별도 수용 시험이 필요합니다. 자동 시험 통과를 이 실기 완료로 간주하지 않습니다.
