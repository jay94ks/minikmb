# USB 경로별 채널 자동 묶음

회로도의 GL3510 포트는 MCU P3↔MS2130 P1, MCU P4↔MS2130 P2입니다.
관리 VID/PID와 HELLO nonce/INFO로 확인한 실리콘 UID를 채널 식별자로 사용하며,
COM 번호나 장치 이름을 채널의 영구 식별자로 사용하지 않습니다.

`topology::pair`는 매번 기존 capture_id를 지운 뒤 현재 Windows 장치 트리로 다시
판정합니다. UI/REST/MCP가 같은 공통 inventory를 사용하며 수동 MCU/영상 묶음이나
임의 기본 카메라 열기로 실패를 우회하지 않습니다.

## 판정 순서

1. UID와 대응하는 관리 장치의 직접 부모가 허용된 GL3510 USB2 허브인지 확인합니다.
   MCU 포트가3/4가 아니면 묶지 않습니다. 각 MCU에 회로도의 slot0/1을 부여합니다.
2. MS2130이 USB2로 열거되면 **MCU와 정확히 같은 직접 부모 허브**의 P1/P2에서
   찾습니다. VID345F/534D·PID2130과 부모 instance ID·포트를 모두 대조합니다.
   하나면 연결하고, 같은 포트에 두 개 이상이면 중복 오류로 연결하지 않습니다.
   이 경우 물리적 부모가 같으므로 USB3 허브나 ContainerId가 없어도 판정할 수 있습니다.
3. 직접 자식 캡처가 없으면 USB3 companion 경로를 검토합니다. 유효한 같은
   ContainerId와 downstream branch를 함께 대조하고 USB2/USB3 허브가 각각 정확히
   하나여야 합니다. 해당 USB2 허브가 MCU의 실제 부모인지 다시 확인한 뒤, 대응
   USB3 허브 P1/P2의 유일한 MS2130만 연결합니다.
4. 조건을 만족하지 않으면 원인을 표시하고 capture_id를 비웁니다. 같은 포트 번호나
   제조사·일반 ContainerId가 같다는 이유로 다른 보드에서 캡처를 빌리지 않습니다.

각 채널을 독립 판정하므로 한 채널의 USB2 경로가 다른 채널의 USB3 경로 선택을
바꾸지 않습니다. 영상 열기는 여전히 명시적 동작이며 전체 앱에서 하나만 허용합니다.
